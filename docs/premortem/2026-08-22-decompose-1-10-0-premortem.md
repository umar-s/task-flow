# Premortem: `decompose` 1.10.0

**Дата:** 2026-08-22 · **Объект:** `docs/superpowers/specs/2026-08-22-task-flow-1-10-0-design.md`
плюс черновик правок (замороженная копия дерева с C1–C14 в том виде, в каком они
были набросаны до панели)
**Углы:** Исполнитель · Противник («зелёный по форме») · Интеграция и
кросс-файловые контракты · Реализм трекеров · Вес и форма — затем панель из
трёх рефутеров (голосование 2 из 3) и критик полноты.
**Формат:** 5 агентов в чистом контексте по спеке и черновику; 91 находка до
дедупа, 68 после; панель рефутеров оставила 20 (+4 спорных, по одному голосу),
44 опровергла — почти все опровергнутые были повторами с другим якорем.
Триаж и решения — владельцем флоу, с проверкой формулировок по тексту.

Отличие от премортема 1.9.0: объектом была не только спека, но и уже
написанный черновик правок, поэтому панель поймала не «что может пойти не
так», а «что уже не сходится между файлами». Две трети принятых дыр — ровно
такие: одна половина контракта объявлена, другая о ней не знает.

## Отклонено

| # | Предложение | Почему нет |
|---|---|---|
| R-1 | Сделать `find_by_key` и `update_issue` обязательными операциями контракта | Контракт растёт на две операции ради случая, который честнее назвать: без поиска re-run не идемпотентен, и dry-run это печатает. `update_issue` — это `create_issue` по найденному id, отдельная операция не нужна иллюстрации |
| R-2 | «Adapter without search → Phase 7 is create-only; a re-run is refused» | Отказ в re-run ломает recovery-путь §8 после сетевого сбоя; предупреждение до подтверждения даёт тот же эффект, решает пользователь |
| R-3 | Ключ guard — `fix_hint`-объект | `fix_hint` между прогонами меняется так же, как description; пометка `repeat: true` самим чекером — единственная сторона, которая видит оба прогона |

## Ревью-панель по коммиту (после премортема)

Пять измерений в чистом контексте по `git diff main..HEAD` (контракты ·
исполнимость · инварианты линта · правила поставки и факты · вес) — 61 находка
до дедупа. Принято и закрыто тем же релизом:

- **`scripts/lint.sh` — лишняя кавычка из 1.9.0** после проверки
  `checkpoint.md` склеивала строку со следующей: проверки `Reviewed:` и
  `review @` не выполнялись, а вторая к тому же смотрела не в тот файл
  (evidence-блок живёт в `land.md` с 1.9.0). Исправлено; негативный контроль
  NC15/NC19.
- Половина инвариантов 1.10.0 была пришпилена заголовком, не правилом (тело
  таблицы удаляется — линт зелёный; severity переписывается — зелёный; девятый
  чек — зелёный). Блок переписан: секция + фраза правила, число секций
  `### Check N` считается, таблицы — по строке заголовка, строки surface — с
  непустым вопросом.
- Контракт без `update_issue` при «update in place» в трёх местах; lookup по
  ключу только среди открытых issue; проход перезаписи id мог затереть
  key-строку; тип issue нигде не выбирался; `plain` для Jira Cloud по REST —
  ложное ограничение (v2 принимает wiki-markup); `fields=` YouTrack не
  возвращал period-значение Estimation; `summary:` без фигурных скобок;
  `--fail-with-body` требует curl ≥ 7.76; два написания строки `Source:`;
  Role чекера перечислял два входа из шести; предикат guard в SKILL и в
  reference не совпадал буквально.
- Вес: эхо-повторы правил вырезаны (SKILL фазы 1/3/5/7, Check 2, §1/§9
  tracker-sync, шаг 7 draft-template) — правила остались там, где их грузят.

## Что не проверялось панелью и осталось на ревью

- Стоимость брифа QA: `qa-checklist.md` (~2,9 тыс. слов) передаётся чекеру на
  каждый check-run (до четырёх) вместе с входом, списками и карточками. Это
  цена независимости чекера; сокращать бриф — отдельная задача, не этот
  релиз.
- Совместимость с issue, созданными 1.x: форма ключа `decompose-id:` не
  менялась намеренно (предложение сменить её отклонено — старые issue перестали
  бы находиться); update in place добавит `Source:` к старым description.

- Acceptance-прогон скилла по установленному плагину (не по копии в
  `~/.claude/skills/`) — после релиза, отдельной сессией.
- Вес: `SKILL.md` +21 % — на уровне 1.9.0; метод ушёл в references
  (+45 % суммарно по пяти затронутым файлам). Следующий релиз `decompose`
  начинается с подрезки, не с добавлений.
