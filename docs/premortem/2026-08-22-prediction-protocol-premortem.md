# Premortem: `prediction-protocol` (design-spec v1)

**Дата:** 2026-08-22 · **Объект:** `docs/superpowers/specs/2026-08-22-prediction-protocol-design.md`
в редакции v1 (до первой строки `hooks.json`, как требовал §10 спеки) плюс
справка по платформе хуков — документация Claude Code и **эмпирические пробы**
на 2.1.239 (см. «Что проверено руками»).
**Углы:** Исполнитель · Противник («зелёный по форме») · Платформа · Интеграция
(task / loop-foundry / co-rar / ci-gate) · Журнал и метрики · Владелец и вес —
затем панель из трёх рефутеров (по тексту спеки / по воспроизведению / по
последствию, голосование 2 из 3) и критик полноты.
**Формат:** Workflow, 10 агентов в чистом контексте, 24 мин; 60 находок после
дедупа по заголовку; панель оставила 20 (+12 спорных, по одному голосу), 28
отвергла — все отвергнутые оказались повторами с другим якорем (ни одной
находки не опровергли по существу). Триаж и решения — владельцем флоу.

Отличие от премортемов 1.9.0/1.10.0: объект — спека без черновика кода, и
панель получила не только текст, но и факты платформы. Две трети принятых дыр
— «спека обещает механизм, которого нет ни в дереве поставки, ни у платформы»
(receipt без привязки, грейдинг без грейдера, fail-closed без trap'а,
классификатор не того объекта). Результат — не правки v1, а v2 с другим центром
тяжести: CLI `predict` как harness, хук — тонкая сверка.

## Что проверено руками (до панели)

Project-level PreToolUse-хук на `Bash`, `claude -p`, haiku, 12 вызовов:

| хук | `-p --allowedTools Bash` | `-p --dangerously-skip-permissions` |
|---|---|---|
| `permissionDecision: deny` | блок, причина уходит модели | блок |
| `exit 2` + stderr | блок | блок |
| `permissionDecision: ask` | блок (некому ответить) | блок |
| `exit 1` + stderr | **команда выполнилась** | выполнилась |
| битый JSON | **выполнилась** | выполнилась |
| таймаут хука | **выполнилась** | выполнилась |

stdin: `session_id, transcript_path, cwd, prompt_id, permission_mode, tool_name,
tool_input{command, description}, tool_use_id`; у вызова из субагента — те же
`session_id` плюс `agent_id`, `agent_type` (хук **срабатывает** в субагентах).
Окружение процесса хука: `CLAUDE_PROJECT_DIR`, `CLAUDE_CODE_SESSION_ID`,
`CLAUDE_CODE_ENTRYPOINT` (`cli` в интерактиве, `sdk-cli` в `-p`);
`CLAUDE_PLUGIN_ROOT` экспортируется плагинным хукам (superpowers читает его из
env в `hooks/session-start`). Эти шесть фактов легли в §5 спеки v2 напрямую.

## Принято (закрыто в спеке v2)

| # | Дыра (панель) | Решение в v2 |
|---|---|---|
| H-1 | P-1/P-12: receipt не привязан ни к команде, ни к сессии — один открытый receipt открывает любую one-way команду на 30 мин из любой сессии; halt не исполняется хуком | `predict open --action '<cmd>'`; хук сравнивает нормализованную `tool_input.command` с receipt'ом **этой сессии** (`session_id` со stdin), одноразовость (`consumed`), один receipt в полёте, TTL от штампа скрипта |
| H-2 | P-2/P-15/P-24/P-36/P-51/P-52: «один список, два потребителя» — `SQL_RE`/`ORM_RE` матчат тело файла миграции, one-way-doors — прозу вопросов; на командной строке это FP на `grep 'DELETE FROM'`, `git branch --delete`, и FN на `alembic upgrade head`, `systemctl restart`, `gh pr merge` | Свой классификатор командной формы (`lib/classify.sh`): глагол по позиции, разбиение составных команд, снятие `sudo`/`env`, `bash -c` рекурсивно; DDL-словарь общий только для ветки inline-SQL; корпуса must-deny и must-pass в `tests/`; `--also` для обёрток проекта |
| H-3 | P-3/P-20/P-21: платформа fail-open (exit 1, битый JSON, таймаут → действие идёт), `set -euo pipefail` + отсутствующий `jq` = гейт молча выключен | `trap` ERR/EXIT → deny-JSON + `exit 2`; единственный явный путь к exit 0; внутренний дедлайн ≤ 10 с при `timeout` 15; парсер `python3 → jq → deny`; негативные контроли на путях ошибок (§10.6) |
| H-4 | P-4/P-17/P-27/P-56: переменная обхода — либо навсегда в `.bashrc`, либо в строке команды, то есть её пишет та же модель; кто пишет запись `bypass` — не сказано | Переменной нет. Обход = клик человека на `ask` и `predict off --reason` (пишет `bypass` в журнал, переводит сессию «вне области»). В headless обхода нет |
| H-5 | P-5/P-53: причина deny — единственная инструкция модели в сессии, не читавшей SKILL; ритуал ~9 вызовов с чтением references | Причина — шаблон: версия, путь к `predict`, строка `predict open …` с подставленной командой; ритуал — 3 вызова (`open` → действие → `close`), references читать не нужно |
| H-6 | P-6: merge/deploy/cache-flush — фаза 8 под `land.md`, куда routing не шёл; `land.md` §6 велит «стоп на permission denied» | Routing в `land.md` §1–§2 (наблюдаемые там уже названы) и §6 («deny гейта — не permission denied: receipt и повтор один раз»); §7 спеки — чеклист поставки 1.11.0 |
| H-7 | P-7/P-13/P-19/P-33/P-44/P-45: hit-rate нечем считать (скрипта нет в дереве), «окно» не определено, INCONCLUSIVE и незакрытые receipt'ы выпадают из знаменателя, в лупах журнал `ladder.md` не имеет поля | `predict report` — единственный источник строки; `rate = HIT/(HIT+MISS+INCONCLUSIVE)`, `O open`, `B bypass`, `n<K → insufficient`; INCONCLUSIVE останавливает как MISS до `retry`/`withdraw`; в лупах — поле `predictions` в существующем jsonl, один журнал |
| H-8 | P-8/P-16/P-25: matcher `mcp__.*__Bash` покрывает несуществующую форму; реальные MCP-инструменты записи без `command` либо не гейтятся, либо fail-closed режет все чтения | 1.0: matcher литерал `Bash`; MCP и PowerShell вне области, заявлено |
| H-9 | P-9/P-30/P-40/P-48: `actual` «дословно» (§3) против «усечённо» (§6), скан «если есть» = fail-open у раковины, журнал пишется через Write, которого matcher не видит | `actual` пишет только `predict close`: значение + ≤ 5 строк/512 байт, встроенные маски всегда, gitleaks когда есть, `redaction:` в записи; значения переменных окружения не попадают |
| H-10 | P-10/P-14: «разобрать команду» не определено; после одного deny модель уносит SQL в файл через Write и запускает `psql -f` | Непрозрачный ввод (`-f`, `<`, heredoc), `ssh`/`docker exec`/`kubectl exec` — one-way по построению; `bash file.sh`/`make` — названный предел + `--also` + правило «обёртка ради обхода = bypass» + ревью читает журнал |
| H-11 | P-11/P-50: `exit code 0` — легальный observable по тексту спеки; тавтология проходит lint и гейт; шум на точном литерале даёт ложные опровержения | Закрытая грамматика `--expect`; для destructive `observe ≠ action` и не только `exit=`; диапазон и regex в грамматике; MISS подтверждается повторным прогоном |
| H-12 | P-18: журнал — редактируемый моделью Markdown; falsifier/prediction переписываются после `actual`; advisory-receipt пишется после взгляда | Receipt живёт в state вне репо, штамп и sha — скриптом; хук при `consumed` проверяет sha; в репо попадает только закрытая запись, которую рендерит `close` |
| H-13 | P-22/P-23/P-31/P-59: сессионно-глобальный хук + fail-closed + журнал по `TASK-ID` = deny во всех проектах без задачи; единственный выключатель — снести плагин | Область = сессия с `predict on` (состояние вне репо, по `session_id`); вне области one-way → `ask` (O7 аудита), нерелевантное → exit 0; fail-closed действует в области |
| H-14 | P-35: loop-foundry не может исполнить контракт — плагина нет в чекауте runner'а, два журнала с двумя схемами, halt некому исполнять в headless | Контракт §7: `predict on --loop` из `run.sh`, GAPS-пункт «CLI доступен, доказано selftest», `predict report --json` → поле `predictions` в jsonl, halt = состояние сессии (хук) + `predict status` для `gates.sh` |
| H-15 | P-37/P-41/P-39: «машинный грейдинг» без машины — модель вставляет `actual` и ставит `verdict`; co-rar Critic — Red Team без интерфейса грейдера, «нечёткий» решает модель | `predict close` исполняет observe и ставит вердикт; модель не пишет `actual`/`verdict` (lint: только со штампом скрипта); несравнимое = INCONCLUSIVE; co-rar из 1.0 убран. | H-16 | P-43: «falsifier, недостижимый для той же команды» — неразрешимо grep'ом | Falsifier не авторится — выводится как дополнение утверждения на той же команде; lint проверяет только грамматику |
| H-17 | P-47/P-58: леджер Refuted write-only — в файле задачи, который следующая задача не открывает; ничто не требует строки на каждый MISS | Один `docs/evidence/REFUTED.md` на репо, пишет только `predict ack`, lint требует строку на каждый MISS; читатель назван — `task` фаза 0, loop-foundry Phase 0 |
| H-18 | P-55/P-29: ветка «с receipt» не описана; симметричный `allow` снимает клик человека на `push --force`; в headless «нет решения = deny» толкает к `allow` на все команды | Таблица режимов §5: с receipt — `ask` с прогнозом в причине (интерактив) / exit 0 (headless); `allow` запрещён lint-grep'ом; нерелевантное — exit 0 пусто |
| H-19 | P-57: advisory-скоуп — «самая ценная территория» — без механизма; отсутствие записи невидимо, hit-rate advisory — самоотбор | Объект со счётчиком: каждый `live`-пункт DoD закрывается через advisory-цикл до взгляда, `DoD-n` цитирует `predict <id>`; пункт без id виден как пункт без улики |
| H-20 | P-28: режим ждали флагом от loop-foundry, хотя `agent_id`/`ENTRYPOINT` уже есть | Режим хук читает сам: `agent_id` → субагент, `CLAUDE_CODE_ENTRYPOINT=cli` → интерактив, иначе headless |
| H-21 | P-49: `<utc>` и `<id>` в заголовке печатала модель — ложные «истёк» по таймзоне или вечные receipt'ы | Штампует скрипт; хук принимает только записи state, которые пишет `predict` |

## Отвергнуто или принято частично

| # | Находка | Почему |
|---|---|---|
| R-1 | P-46 (часть): исключить `docs/evidence/` из диапазона диффа ревью 6 | Закрытая запись журнала — артефакт флоу того же рода, что спека и premortem edges; ревьюер их получает. Открытые receipt'ы в дифф не попадают (H-23), этого достаточно |
| R-2 | Критик: пин тега в `marketplace.json` для этого плагина | Противоречит конвенции каталога («ref не пинится, релизного шага нет»); исключение ради одного плагина — второе правило для того же места. Компенсация: версия в причине, CI-матрица, `predict off` |
| R-3 | P-50 (часть): обязательный `--baseline` для destructive | Дополнительный прогон измерения на каждое действие — вес; оставлен опциональным с WARNING в lint на «прогноз равен baseline» |
| R-4 | P-57 (часть): `journal-lint` читает таблицу DoD спеки и печатает `live items unpredicted: K` | Кросс-плагинный парсинг чужого артефакта — именно то, что H-22 запрещает; покрытие видно в evidence-блоке по отсутствию `predict <id>` у пункта |
| R-5 | P-26/P-37 (часть): «гейт непроходим ровно на один Write» — receipt пишет та же модель, значит слой не deterministic | Принято как формулировка (слой назван честно), не как отказ от гейта: по форме хук deterministic, по значению грейдер deterministic; что модель авторит гипотезу — свойство задачи, а не дефект. ARC тоже принимал прогноз от модели |
| R-6 | P-28 (часть): субагент с receipt → `deny` вместо «пусть оркестратор решит» | Принято как есть: субагент one-way дверь не открывает, это делает оркестратор — O8-light, дешевле, чем второй канал |

## Что не проверялось

- Поведение `permissionDecision: ask` в **интерактивном auto-режиме** (виден
  ли текст причины в промпте и остаётся ли клик) — проверено только в `-p`;
  проверить при acceptance-run плагина через установленную копию.
- Экспорт `CLAUDE_PLUGIN_ROOT`/`CLAUDE_PLUGIN_DATA` в процесс хука — по
  косвенному свидетельству (superpowers читает `CLAUDE_PLUGIN_ROOT` из env);
  `CLAUDE_PLUGIN_DATA` в спеке не используется.
- Фактический вес SKILL.md и стоимость ритуала в токенах — до черновика.
- Панель не видела кода — ревью-панель по черновику плагина запускается
  отдельно (как в 1.10.0), в том числе с негативными контролями §10.
